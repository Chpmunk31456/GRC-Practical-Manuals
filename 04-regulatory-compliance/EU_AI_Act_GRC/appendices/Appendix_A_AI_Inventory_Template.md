# Appendix A — AI Inventory Template

## Purpose

Use this template to maintain a complete, current, and auditable record of AI systems, models, components, and use cases across the organization.

## Inventory fields

| Field | Required information |
|---|---|
| Inventory ID | Unique identifier |
| System name | Official business and technical name |
| Business owner | Accountable executive or process owner |
| Technical owner | Accountable technical lead |
| Legal entity | Entity operating or providing the system |
| Countries | Jurisdictions where developed, offered, or used |
| Lifecycle stage | Idea, pilot, development, validation, production, suspended, retired |
| Intended purpose | Approved purpose and decision context |
| Users | Internal users, customers, public, regulators, or others |
| Affected persons | Individuals or groups materially affected |
| AI technique | Model type, rules, ML, generative AI, agentic AI, hybrid |
| Provider or vendor | Internal team or external supplier |
| Model and version | Current production model and release |
| Data sources | Training, tuning, retrieval, input, and monitoring data |
| Outputs | Predictions, rankings, recommendations, content, decisions, actions |
| Human oversight | Review, approval, override, appeal, and escalation controls |
| EU AI Act role | Provider, deployer, importer, distributor, product manufacturer, GPAI provider, other |
| Risk classification | Prohibited, high-risk, transparency duty, GPAI, limited/minimal risk, pending |
| Sector classification | Employment, credit, travel, health, public services, safety, other |
| Fundamental-rights impact | None, low, moderate, high, pending assessment |
| Personal data | Yes/no and data categories |
| Sensitive data | Yes/no and categories |
| Security classification | Public, internal, confidential, restricted |
| Vendor dependencies | Models, APIs, cloud services, subprocessors, data providers |
| Required assessments | Applicability, prohibited practice, high-risk, FRIA, DPIA, security, conformity, vendor |
| Transparency duties | Notices, labels, instructions, disclosures |
| Monitoring | Performance, drift, bias, security, incidents, complaints |
| Evidence location | Repository or system of record |
| Approval status | Approved, conditional, rejected, suspended, retired |
| Last review date | Date of latest formal review |
| Next review date | Scheduled reassessment date |
| Open findings | Material issues, exceptions, and remediation |

## Minimum control requirements

- Assign accountable business and technical owners.
- Record every material production, pilot, and externally supplied AI use.
- Link each entry to classification, risk, vendor, and evidence records.
- Reconcile inventory entries to procurement, cloud, security, data, and development records.
- Review after material changes, incidents, new jurisdictions, or vendor updates.
- Retain historical versions and retirement evidence.
