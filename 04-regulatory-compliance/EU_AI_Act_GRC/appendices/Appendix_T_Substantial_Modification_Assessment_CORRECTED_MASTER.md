# Appendix T — Substantial-Modification Assessment

> **Legal status:** Corrected English master. Use the current statutory definition and actor-specific rules. A material operational change is not automatically a substantial modification, and a substantial modification can transfer provider responsibilities and trigger renewed conformity obligations.

## 2. Threshold test

Assess whether the change was unforeseen or not planned in the initial conformity assessment and whether it affects compliance with applicable requirements or changes the intended purpose.

| Question | Yes/No/Uncertain | Evidence |
|---|---|---|
| Was the change predetermined and documented in the original technical documentation/change plan? | | |
| Does the change alter intended purpose? | | |
| Does it affect compliance with Articles 9–15 or other applicable requirements? | | |
| Does it change classification, product integration, or conformity route? | | |
| Does it materially affect performance, safety, rights, data governance, oversight, transparency, robustness, or cybersecurity? | | |
| Does it introduce a new model, architecture, autonomous capability, population, or decision context? | | |
| Does it weaken or remove safeguards? | | |

## 3. Provider-role consequence

Determine whether the modifying deployer, distributor, importer, or other third party becomes the provider under the applicable value-chain rule. Record branding, own-name placement, intended-purpose change, and substantial-modification facts separately.
