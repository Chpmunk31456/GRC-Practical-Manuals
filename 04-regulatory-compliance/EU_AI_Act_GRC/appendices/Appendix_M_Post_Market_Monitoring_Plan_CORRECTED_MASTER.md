## 2. Monitoring design

Define a documented, proportionate, active, and systematic process for collecting, documenting, and analysing relevant data throughout the system lifetime.

| Indicator | Baseline | Warning | Critical | Source | Frequency | Owner |
|---|---|---|---|---|---|---|
| | | | | | | |

Cover performance, accuracy, robustness, cybersecurity, safety, fundamental rights, subgroup outcomes, human oversight, transparency, complaints, incidents, misuse, dependency changes, and control failures as applicable.

## 3. Data and evidence

Record logs, sampled inputs/outputs, overrides, complaints, incidents, near misses, vendor notices, drift tests, audit findings, authority communications, and version/configuration changes. Apply privacy, minimisation, retention, confidentiality, and integrity controls.

## 4. Trigger and response matrix

| Trigger | Required action | Actor/owner | Deadline/source | Evidence |
|---|---|---|---|---|
| | | | | |

Possible actions include investigation, enhanced oversight, restriction, suspension, correction, withdrawal, recall, supplier escalation, documentation update, conformity reassessment, and regulatory notification where legally required.

## 5. Plan integration

Link the plan to risk management, quality management, technical documentation, incident reporting, corrective action, change management, and regulatory response.
