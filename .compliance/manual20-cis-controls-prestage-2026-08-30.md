# Manual 20 — CIS Controls Pre-stage

Pre-stage Manual 20 so the Manual 19 -> Manual 20 handoff does not create an idle gap.

## Source family

Center authoritative verification on the Center for Internet Security (CIS) Controls and related official CIS implementation material. Release-time verification must confirm the then-current Controls version, implementation-group guidance, mappings, safeguards terminology, and any licensing/use restrictions relevant to publication.

## Controlled architecture targets

- applicability and organizational profile;
- implementation groups and prioritization;
- inventory and control ownership;
- asset/software/data/account management;
- secure configuration;
- vulnerability and patch management;
- access control and identity;
- logging and monitoring;
- email/browser/malware defenses;
- data recovery;
- network infrastructure and monitoring;
- security awareness;
- service-provider management;
- application security;
- incident response;
- penetration testing;
- evidence, metrics, exceptions and continuous improvement;
- crosswalks without claiming equivalence to regulatory compliance.

## Prebuild rule

Once Manual 19 moves into active build, Manual 20 must immediately move beyond pre-stage into controlled build. Publication remains sequential.
