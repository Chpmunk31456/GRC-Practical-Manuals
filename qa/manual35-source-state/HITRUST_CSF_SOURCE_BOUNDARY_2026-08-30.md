# Manual 35 — HITRUST CSF authoritative source-state decision

## Controlled baseline

Manual 35 uses HITRUST CSF v11.8.0 as the current controlled framework baseline. HITRUST announced v11.8.0 on 2026-05-07 and made it available in MyCSF on 2026-05-08. Earlier v11.x releases remain relevant only for transition/history where HITRUST's assurance-program rules still permit an existing assessment to continue.

## Framework and assurance boundary

The manual must distinguish the HITRUST CSF framework from the HITRUST Assurance Program and from any organization-specific certification result. e1, i1, and r2 assessments have different assurance purposes and lifecycle rules. Version eligibility, creation deadlines, submission deadlines, requirement-statement changes, and authoritative-source mappings must be reverified against current HITRUST advisories before publication or assessment-readiness claims.

The current source state must not be inferred from legacy v9.x, v10.x, or earlier v11.x material in the repository. Any reused implementation guidance must be reconciled against v11.8.0 and the then-current assurance-program advisories.

## Proprietary-source boundary

HITRUST framework and assurance materials contain proprietary content. The repository may record public version metadata, original implementation architecture, evidence models, readiness procedures, control-family concepts, assessment workflow guidance, and organization-authored crosswalk reasoning, but must not reproduce restricted HITRUST content beyond what is licensed or otherwise permitted.

No manual statement may imply that this project is HITRUST, is endorsed by HITRUST, or can confer HITRUST certification. Certification and validated-assessment outcomes remain dependent on the official HITRUST program, licensed tooling/content where required, and authorized assessor processes.

## Controlled architecture targets

The 32-chapter architecture will cover governance, scope and organizational factors, risk analysis, control selection and tailoring, e1/i1/r2 assurance distinctions, policy and procedure evidence, implementation evidence, sampling and testing preparation, corrective action, inheritance and shared responsibility, third-party assurance, cloud and technology mappings, privacy/security integration, authoritative-source mapping, MyCSF workflow boundaries, readiness assessment, assessor interaction, quality assurance, evidence retention, version transition, remediation, certification-maintenance boundaries, metrics, and executive reporting.

## Release boundary

Immediately before publication, reverify the active HITRUST CSF version, current Assurance Program advisories, supported assessment-object creation/submission rules, and any announced version transition. Proposed or request-for-comment changes must not be represented as effective requirements before HITRUST makes them effective.

Localization, editorial review, rendered accessibility/visual review, provenance/checksums, workflow security, reproducible exact artifacts, any required genuine-human substantive review, predecessor publication, and final catalog/release-registry reconciliation remain fail-closed.

Publication remains sequential behind Manuals 18–34.
